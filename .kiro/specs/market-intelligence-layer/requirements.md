# Requirements Document

## Introduction

The Market Intelligence Layer adds evidence-backed trend and competitor intelligence to the AutoMind AI marketing pipeline. Currently, the MarketResearchAgent generates research purely from LLM inference based on scraped website data. This upgrade introduces a TrendSnapshot and CompetitorSnapshot data layer that feeds real-world intelligence signals into the research generation prompt, producing grounded, evidence-backed ResearchSnapshots. The intelligence layer is reusable by all current and future agents (PersonaAgent, HookAgent, CaptionAgent, HashtagAgent, SEOAgent, AdCopyAgent).

## Glossary

- **Market_Intelligence_Service**: The service class responsible for aggregating trend and competitor intelligence data, managing cache validity, and orchestrating Bedrock generation of intelligence snapshots.
- **TrendSnapshot**: A database-persisted record containing trending keywords, hashtags, content formats, and CTA styles for a given industry and platform.
- **CompetitorSnapshot**: A database-persisted record containing competitive positioning, strengths, weaknesses, messaging angles, and content opportunities for competitors in a given industry.
- **MarketResearchAgent**: The existing agent that scrapes a website and generates a ResearchSnapshot via Bedrock. This agent is upgraded to consume intelligence data before generating research.
- **ResearchSnapshot**: The existing database model storing the final research output (company summary, market position, core benefits, competitor summary, keywords, target audience).
- **Bedrock_Provider**: The AWS Bedrock Claude LLM provider used for text and JSON generation.
- **Cache_TTL**: The 24-hour time-to-live period for TrendSnapshot and CompetitorSnapshot records, after which they are considered expired and must be regenerated.
- **Intelligence_Dict**: The combined dictionary returned by Market_Intelligence_Service containing scraped website data, trend data, and competitor data.

## Requirements

### Requirement 1: TrendSnapshot Persistence

**User Story:** As a marketing platform operator, I want trend intelligence stored in the database with an expiration marker, so that the system can serve cached trends without redundant LLM calls.

#### Acceptance Criteria

1. THE TrendSnapshot model SHALL store id (UUID string primary key), industry (indexed string), platform (string), keywords (JSON list), hashtags (JSON list), content_formats (JSON list), cta_styles (JSON list), captured_at (DateTime, indexed), and expires_at (DateTime).
2. WHEN a TrendSnapshot is created, THE TrendSnapshot model SHALL set expires_at to captured_at plus 24 hours.
3. THE TrendSnapshot model SHALL restrict the platform field to one of: instagram, tiktok, linkedin, youtube, twitter, google.
4. THE TrendSnapshot model SHALL index the industry and captured_at columns for efficient cache lookups.

### Requirement 2: CompetitorSnapshot Persistence

**User Story:** As a marketing platform operator, I want competitor intelligence stored in the database with an expiration marker, so that the system can serve cached competitor analysis without redundant LLM calls.

#### Acceptance Criteria

1. THE CompetitorSnapshot model SHALL store id (UUID string primary key), industry (indexed string), competitor_name (string), strengths (JSON list), weaknesses (JSON list), positioning (Text), messaging_angles (JSON list), content_opportunities (JSON list), keywords (JSON list), created_at (DateTime), and expires_at (DateTime).
2. WHEN a CompetitorSnapshot is created, THE CompetitorSnapshot model SHALL set expires_at to created_at plus 24 hours.
3. THE CompetitorSnapshot model SHALL index the industry column for efficient cache lookups.

### Requirement 3: Trend Intelligence Generation

**User Story:** As a marketing platform operator, I want trending keywords, hashtags, and content formats generated by Bedrock for a given industry, so that research outputs are grounded in current market signals.

#### Acceptance Criteria

1. WHEN Market_Intelligence_Service generates trend data, THE Bedrock_Provider SHALL receive a prompt requesting trending keywords, hashtags, content formats, and CTA styles for the specified industry.
2. WHEN the Bedrock_Provider returns trend data, THE Market_Intelligence_Service SHALL persist a new TrendSnapshot record with the generated data and a captured_at timestamp of the current time.
3. THE Market_Intelligence_Service SHALL generate trend data for at least one platform relevant to the industry.
4. IF the Bedrock_Provider fails to generate trend data, THEN THE Market_Intelligence_Service SHALL log the error and return an empty trend dataset rather than raising an unhandled exception.

### Requirement 4: Competitor Intelligence Generation

**User Story:** As a marketing platform operator, I want competitive positioning and messaging angles generated by Bedrock for a given industry, so that research outputs incorporate competitive awareness.

#### Acceptance Criteria

1. WHEN Market_Intelligence_Service generates competitor data, THE Bedrock_Provider SHALL receive a prompt requesting competitor names, strengths, weaknesses, positioning, messaging angles, content opportunities, and keywords for the specified industry.
2. WHEN the Bedrock_Provider returns competitor data, THE Market_Intelligence_Service SHALL persist one or more CompetitorSnapshot records with the generated data and a created_at timestamp of the current time.
3. IF the Bedrock_Provider fails to generate competitor data, THEN THE Market_Intelligence_Service SHALL log the error and return an empty competitor dataset rather than raising an unhandled exception.

### Requirement 5: Intelligence Cache Strategy

**User Story:** As a marketing platform operator, I want intelligence data cached per industry for 24 hours, so that repeated requests within the TTL avoid redundant LLM calls and reduce latency.

#### Acceptance Criteria

1. WHEN Market_Intelligence_Service receives a request for trend data, THE Market_Intelligence_Service SHALL query the database for TrendSnapshot records WHERE industry matches the requested industry AND expires_at is greater than the current time.
2. WHILE a valid (non-expired) TrendSnapshot exists for the requested industry, THE Market_Intelligence_Service SHALL return the cached TrendSnapshot data without calling Bedrock_Provider.
3. WHEN no valid TrendSnapshot exists for the requested industry, THE Market_Intelligence_Service SHALL generate new trend data via Bedrock_Provider and persist a new TrendSnapshot.
4. WHEN Market_Intelligence_Service receives a request for competitor data, THE Market_Intelligence_Service SHALL query the database for CompetitorSnapshot records WHERE industry matches the requested industry AND expires_at is greater than the current time.
5. WHILE valid (non-expired) CompetitorSnapshot records exist for the requested industry, THE Market_Intelligence_Service SHALL return the cached CompetitorSnapshot data without calling Bedrock_Provider.
6. WHEN no valid CompetitorSnapshot records exist for the requested industry, THE Market_Intelligence_Service SHALL generate new competitor data via Bedrock_Provider and persist new CompetitorSnapshot records.

### Requirement 6: Intelligence Aggregation Interface

**User Story:** As a developer integrating agents, I want a single method that returns combined intelligence data (website scrape + trends + competitors), so that any agent can obtain full market context with one call.

#### Acceptance Criteria

1. THE Market_Intelligence_Service SHALL expose a method get_intelligence that accepts industry, website_url, and product_name as parameters.
2. WHEN get_intelligence is called, THE Market_Intelligence_Service SHALL return an Intelligence_Dict containing: scraped website data (from analyze_website), trend data (from cached or freshly generated TrendSnapshot), and competitor data (from cached or freshly generated CompetitorSnapshot).
3. WHEN get_intelligence is called with a website_url, THE Market_Intelligence_Service SHALL invoke analyze_website to obtain scraped data.
4. IF analyze_website fails, THEN THE Market_Intelligence_Service SHALL include fallback empty scrape data in the Intelligence_Dict and continue processing trend and competitor data.

### Requirement 7: MarketResearchAgent Intelligence Integration

**User Story:** As a marketing platform user, I want the research agent to synthesize real market intelligence data rather than hallucinating research, so that generated research is evidence-backed and trustworthy.

#### Acceptance Criteria

1. WHEN MarketResearchAgent executes, THE MarketResearchAgent SHALL call Market_Intelligence_Service.get_intelligence before calling Bedrock_Provider for the final research generation.
2. WHEN MarketResearchAgent builds the Bedrock prompt, THE MarketResearchAgent SHALL include trend keywords, hashtags, content formats, competitor positioning, and messaging angles from the Intelligence_Dict in the prompt context.
3. THE MarketResearchAgent research prompt SHALL instruct Bedrock_Provider to synthesize the provided intelligence data rather than invent new market information.
4. WHEN MarketResearchAgent completes, THE ResearchSnapshot SHALL contain research grounded in the intelligence data provided in the prompt context.

### Requirement 8: No Additional Credit Cost

**User Story:** As a marketing platform user, I want the intelligence gathering step to be transparent and free, so that my credit balance is not affected by the system's internal optimization.

#### Acceptance Criteria

1. THE MarketResearchAgent SHALL maintain its existing credit cost of 5 credits per execution.
2. THE Market_Intelligence_Service trend and competitor generation calls SHALL NOT trigger any additional credit reservation or deduction beyond the existing MarketResearchAgent cost.

### Requirement 9: Reusable Intelligence Interface

**User Story:** As a platform developer, I want the intelligence layer to be callable by any agent independently, so that future agents (CaptionAgent, HashtagAgent, SEOAgent, AdCopyAgent) can access trend and competitor data directly.

#### Acceptance Criteria

1. THE Market_Intelligence_Service SHALL be instantiable with a database session parameter, independent of any specific agent lifecycle.
2. THE Market_Intelligence_Service SHALL expose get_intelligence as an async method callable from any agent or service without coupling to MarketResearchAgent.
3. THE Market_Intelligence_Service SHALL expose individual methods for retrieving trend data and competitor data separately, allowing agents to request only the intelligence type they need.
